# 本地 Teammate 完成通知

此机制只覆盖同一进程中的本地团队，与跨节点 A2A 无关。

## 调用链

Lead 的 `spawn_agent(background=true)` 或 `assign_task(background=true)` 通过工具执行上下文捕获本轮 Lead 的 session ID，并将父 Agent ID、session ID、子 Agent ID 和可选 Task ID 传给 `SubAgentRuntime.spawnInBackground`。运行时为每次执行生成独立 ID；Promise 最终成功、失败或中断时，调用 `TeamRuntime.notifyBackgroundCompletion`，将终态和最多 500 字的摘要放入本地 `Mailbox`。会话归属来自派发时的上下文，而不是完成时当前显示的会话。重复的同一执行 ID 不会再次入队。

正在执行的 Lead 在 Agent Loop 每个步骤开始时领取属于自己及当前 session 的通知，持久记录为团队邮箱消息后 ACK；不会打断正在执行的模型或工具调用。写入失败时 NACK，下一轮可重试；如写入已经发生但随后报错，通过持久会话中的消息 ID 识别该记录，避免再次写入。同一批消息逐条确认，已成功记录的消息不会因后续消息失败而全部重投。

交互式 CLI 使用 `LeadWake` 监听完成事件，只有主会话处于输入等待且事件属于当前会话时才安排后续轮次。轮次之间还会检查未读通知，覆盖运行结束与进入输入等待之间的竞态。多个通知可以合并到同一轮。CLI 主循环串行执行 Lead 轮次，用户输入和自动唤醒不能并发启动两轮；若用户先提交输入，通知会在该轮的步骤边界进入上下文。自动轮次保留尚未提交的输入草稿及光标位置。切换到其他会话后，原会话的通知留在内存邮箱，恢复原会话时安排处理；不会为旧会话在后台切换共享的 ContextManager。CLI 退出时关闭唤醒监听并销毁团队运行时。若自动处理失败，针对同一组未读通知不会无限重复启动；用户可发起新一轮重试，或新的完成通知可触发再次处理。

通知只是执行终态和简短摘要，**不代表任务产物已验证**。通过 `wait_agent` 使用 Agent ID 获取完整执行结果；若该成员已再次执行，传入通知中的 `Notification ID` 作为 `executionId` 可以读取对应的旧结果。较大的工具结果仍走现有结果截断与 `read_tool_result` 机制；通过任务状态和工作区检查产物。多个成员仍在运行时，可使用 `wait_for_change` 等待本地团队事件，再检查通知及结果；`wait_agent` 仍支持等待指定成员。成员权限、写入范围和沙箱规则不因通知改变。

## 边界

- 邮箱、通知去重集合和后台 Promise 均在进程内；进程退出或重启后尚未投递的通知及 `wait_agent` 的内存结果不会保留，不提供跨进程恰好一次投递。已经写入会话历史的通知按现有会话存储保留。
- 目前自动启动后续轮次仅接入交互式 CLI 的 Main；非交互式 CLI 是单次输入并退出，不维持空闲会话。其他调用 `runAgentLoop` 的入口需要自行管理轮次和唤醒，不能假设入队会自动运行。后台子 Agent 的会话也没有独立空闲轮次调度器。
- `wait_agent` 不指定执行 ID 时读取该 Agent 最近一次后台执行；指定通知中的执行 ID 可读取该进程内保留的相应结果。CLI 会话切换保留共享的任务板和 Agent 注册表，避免清除仍在运行或尚待查阅的任务；它们不按会话隔离，本机制只对完成通知做会话隔离。
- 自动唤醒不恢复已关闭的进程或团队。会话切换不是关闭：只要同一进程仍在运行，原会话的内存通知可在恢复时处理。
