# 备份与恢复

备份覆盖两类存储：产品目录和可选外部 PostgreSQL。只备份源码、只备份 SQLite、或只保留主密钥都不能恢复完整服务。

## 一致性备份

1. 记录源码 Git commit、配置版本、Node/helper 版本，以及实际 `NASH_HOME`。
2. 暂停任务提交，处理进行中的任务和外部副作用；使用 `node dist/index.js stop` 停止本产品实例。
3. 将完整产品目录备份到仓库外受保护位置，包括 `product.db`、匹配的 `master.key`、节点身份、状态文件、会话、Artifact 及存在的 SQLite 辅助文件。不要只复制正在写入的数据库文件。
4. 若使用 PostgreSQL，使用专用账户和 `pg_dump` 制作同一停机窗口的逻辑备份。通过受保护的连接配置提供密码，不能放在 argv 或日志。
5. 对备份计算摘要并记录时间；限制访问，按组织策略加密和保留。备份中含真实凭据，不能提交到 GitHub。
6. 启动原实例并检查身份、模型配置和项目授权。

安装器不会自动覆盖数据库、恢复备份或删除历史数据。

## 恢复

使用隔离目标，先确认不会同时启动同一节点身份。选择匹配的程序版本，保持原产品目录权限，原样恢复完整目录和相应外部数据库。没有匹配 master.key 时不要初始化新的密钥覆盖旧库。

恢复后先 `config validate` 和 `doctor`，再启动。核对管理员、模型关系、Worker 身份、项目、会话及 Artifact SHA-256；对中断任务检查真实副作用，不能直接标记完成或重放。

灾难恢复与配置版本回滚是不同操作。配置回滚不会回滚数据库 schema、任务产生的文件或外部系统副作用。
