# Web 控制台

从启动输出获取实际地址，使用初始化创建的管理员登录。界面可显示 Dashboard、Chat、Tasks、Graphs、Nodes、Projects、Models、Security、Approvals、Artifacts、Settings 与 Diagnostics；能否完成具体操作应以真实后端请求和保存结果为准。

## 推荐流程

1. **Diagnostics**：检查版本、连接和系统能力，不把诊断页面渲染当成服务健康证明。
2. **Models**：填写协议、服务地址、模型名称及新凭据；测试文本和工具能力后再应用。已保存密钥只显示配置状态。
3. **Security**：选择工作区、网络和审批限制，核对配置版本和适用节点。
4. **Projects**：添加当前节点能够访问且已授权的真实路径。
5. **Nodes**：使用一次性邀请加入真实 Worker，检查在线身份和能力。
6. **Chat**：先执行只读任务，再按需要批准写操作。
7. **Tasks/Graphs/Artifacts**：核对工具事件、依赖、终态和实际产物。

## 二次配置

先保存一份当前有效配置的版本标识。修改后关注校验反馈；发生版本冲突时刷新后重新审阅，不覆盖其他管理员的修改。模型测试失败时保留当前有效配置；需要恢复时通过受支持的配置版本恢复操作，恢复后再次发起新任务核对。

新任务应采用新配置，正在进行的模型请求保留其确定版本。端口、监听地址、数据库等启动参数可能需要计划内重启；不要把表单保存成功等同于现有进程已经切换连接。

用户管理、备份恢复和节点撤销等操作必须核对返回结果。高级 API 能力存在不代表每个页面都已提供完整向导；未实现的交互应记录到 Remaining Issues，不能用 Mock 结果补齐。
